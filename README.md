# 银行柜面信息录入练习模拟器

仿真银行柜面业务系统界面的录入练习工具：右侧给出「客户资料/待核对数据」，按左侧表单逐项录入，提交后判分。
纯前端单文件，零依赖，打开 `index.html` 即用。

**在线访问：** https://putaodongningcha.github.io/bank-entry-practice/

## 已收录题型

| 题型 | 说明 | 需录入字段 |
| --- | --- | --- |
| 长期不动户核销 | 先输账号+币种查询，系统带出不动户信息与费用信息，再录核销信息与经办人信息 | 12 项 |
| 确认大额贷记 | 确认类交易，数据已带出、无需查询，逐项核对录入（金额大写由系统自动生成） | 13 项 |
| 混合练习 | 从全部题型中随机抽题 | — |

## 核心技能点

资料栏显示的是**中文语义值**，表单要填的是**编码**——这正是柜面录入的真实技能点：

| 资料栏 | 表单要填 |
| --- | --- |
| 是否收回欠费：否 / 是 | `0` / `1` |
| 核销方式：支取销户 / 转损益 / 损益支取 | `0` / `1` / `2` |
| 是否计息：否 / 是 | `0` / `1` |

## 两种模式

- **练习模式（默认）**：不限时；提交本题后逐字段标出对错并给出正确答案，错项置顶显示，可修正后再进下一题。
- **考试模式**：倒计时（15/30/45 分钟可选）、题量可选（10/20/50/120），提交后不即时判分，交卷统一给出成绩单。

## 成绩单

完全正确题数、字段正确率、总用时、平均每题用时，外加**易错字段排行**（帮你定位最该练的字段）和逐题错项明细。

## 造题说明

- 身份证号码按 GB 11643-1999 生成合法校验位，证件有效期由出生日期推算（46 周岁以上为长期）
- 欠费金额 = 应收费用 − 已收费用，数据自洽
- 大额贷记金额为 12~15 位，按字符串生成（超出 JS 安全整数范围，不能用浮点算）
- 金额大写按银行口径自动生成，已用 16 个算例覆盖零位补齐规则

## 快捷键

- **Enter / Tab**：跳到下一个录入框；在最后一格按 Enter 直接提交本题
- 系统带出的只读框不参与跳转，回车会落到第一个空着的录入框
- 输入全角数字会被自动转半角，判分容忍

## 手机端

窄屏（≤820px）自动切换为移动布局，手机上也能正常练：

- 控制条压缩为三行；**资料栏前置**并压成一行（倒计时 / 题目数 / 提交试卷）
- 表单改为**单列**，输入框放大到 30px 高、字号 16px（16px 是 iOS 不自动放大聚焦的阈值）
- 资料栏**点标题即可折叠**（`▾/▸`），抄完资料收起它给表单腾地方；内容超高时内部滚动
- 长提示文字可换行，不会被挤出屏幕（桌面端「核销方式」的 0/1/2 说明含按钮，手机上按钮自动换行）
- 成绩单指标改为两列

## 扩展新题型

题型由注册表驱动，加题型只需在 `TYPES` 里加一段定义（表单结构、数据生成、判分字段都由它派生）：

```js
const TYPES = {
  '新题型键': {
    name:'题型名称', queryBy:['acct'],        // queryBy 为空表示无需查询步骤
    gen: () => ({ /* 字段数据 */ }),
    fields:{ acct:{label:'账号', enter:true}, /* enter=人工录入并判分，ro=系统带出 */ },
    groups:[ {title:'分组名', cols:3, cells:[{k:'acct'}]} ]
  }
};
```

## 修复记录

- **币种下拉框开局空白**：`clearForm()` 对 select 也用了 `el.value=''`，没有任何 option 匹配会令 `selectedIndex` 变 -1，查询永远取不到币种；改用 `selectedIndex = 0` 复位。
- **混合练习交卷抛异常**：统计分母取了 `TYPES[S.type]`，而混合模式下 `S.type` 是 `__mix` 取不到定义；改为按每题自己的题型取字段数。
- **考试模式判定区全程空白**：提交反馈写在 `loadQuestion()` 之前，会被 `clearForm()` 重置掉；改到其后渲染。
- **判定区看不出反馈**：默认模式改为练习模式；未查询就提交时判定区同步显红说明原因，不再只在底部状态条提示。
